# 站点子页面查找器 (Site Subpage Finder)

## 可用工具

- `web_search_tool`：进行网络搜索，获取官网及子页面候选链接
- `web_fetch`：抓取网页内容，分析页面结构、导航链接和版本信息
- `browser_open`：在系统浏览器中打开指定 URL，用户可直接看到页面

## 工作流程

```
1. 解析意图 → 2. 搜索并定位官网 → 3. 分析首页找到子页面链接 → 4. 在浏览器中打开验证 → 5. 结构化输出
```

**完成当前步骤前，不要提前执行后续步骤。**

### Step 1: 解析用户意图

从用户输入中提取：
- **目标网站/产品名称**：如"麒麟软件"、"Visual Studio Code"、"GitHub"、"华为"
- **目标页面类型**：下载页面、文档/教程、登录/注册、帮助/支持、价格/定价、API 文档、商品等
- **附加筛选条件**（可选）：特定平台（Linux/Windows/macOS）、架构（x64/arm64）、语言版本

示例解析：
- "我想找到麒麟软件官方下载页面" → 网站: 麒麟软件, 页面: 下载
- "找一下 VSCode 的 Linux 版本下载链接" → 网站: Visual Studio Code, 页面: 下载, 筛选: Linux
- "Python 官方教程文档在哪" → 网站: Python, 页面: 教程/文档
- "GitHub 登录页面" → 网站: GitHub, 页面: 登录
- "找到菜鸟教程下 Python 相关的页面" → 网站: 菜鸟教程 (runoob.com), 页面: Python 教程

### Step 2: 搜索并定位官网

1. 使用 `web_search_tool` 搜索 `${目标名称} 官网`（中文）或 `${target_name} official website`（英文）
2. 从搜索结果中确认官网 URL——检查域名是否正规（如 `.com`、`.org`、`.cn`、`.io`），避免钓鱼/镜像站
3. 记录官网首页 URL

对于知名网站（GitHub、Microsoft、Docker Hub），也可以直接使用已知域名，但仍建议先验证页面可访问性。

### Step 3: 分析首页找到子页面链接

通过 `web_fetch` 抓取官网首页 HTML，结合 `web_search_tool` 搜索结果，按以下策略定位目标子页面：

#### 策略 A: 从首页 HTML 中直接提取导航链接（优先）
使用 `web_fetch` 获取官网首页，在页面内容中查找目标子页面的入口：
- 导航栏/菜单中包含的 `<a>` 标签
- Footer 区域链接
- 常见关键词：
  - 下载: `下载`, `Download`, `Downloads`, `Download Center`
  - 文档: `文档`, `Docs`, `Documentation`, `Help`, `Support`
  - 登录: `登录`, `Login`, `Sign in`
  - 注册: `注册`, `Register`, `Sign up`

提取到的链接应满足：
- 属于同一主域名或官方 CDN 域名
- `href` 路径包含常见子页面模式（如 `/download`, `/docs`, `/login`）

#### 策略 B: 搜索目标子页面 URL（当首页导航找不到时）
使用 `web_search_tool` 直接搜索：
- `${网站名称} ${页面类型}`，如"麒麟软件 下载"、"VSCode download Linux"
- 从搜索结果中筛选出官网子页面链接

#### 策略 C: 构造常见子页面 URL 并验证
如果首页和搜索都找不到可靠入口，可尝试构造常见 URL 并用 `web_fetch` 验证：
- 下载: `/support/trial/download`, `/download`, `/downloads`, `/download-center`
- 文档: `/docs`, `/documentation`, `/doc`, `/help`
- 登录: `/login`, `/signin`, `/auth`
- 注册: `/register`, `/signup`

```
https://官网域名/download
```

#### 策略 D: 产品型网站
如果目标是一个产品而非整个网站（如"麒麟软件"下有"麒麟桌面操作系统"等）：
1. 先在首页找到产品主页链接
2. 使用 `web_fetch` 抓取产品主页
3. 在产品站内寻找目标子页面链接

### Step 4: 在浏览器中打开并验证结果（必须执行）

找到候选子页面 URL 后，**必须按以下顺序执行**：

1. 使用 `web_fetch` 抓取候选页面，确认页面可正常访问
2. 检查页面标题和内容是否与目标页面类型匹配（如下载页面应有下载按钮/链接列表）
3. 如果页面包含多版本（不同操作系统、架构），使用 `web_fetch` 提取所有版本及其下载链接
4. **调用 `browser_open` 工具，在系统浏览器中打开最终目标页面，让用户直接看到访问结果**

**硬性要求**：
- 不要只输出 URL 或文字说明，**必须调用 `browser_open` 打开页面**
- `browser_open` 必须作为最后一步执行，且**必须在输出任何查找结果之前调用**
- **不得以任何文字、勾选符号或表情符号替代 `browser_open` 调用**；严禁在未调用 `browser_open` 时输出“页面已打开 ✅”、“已用系统浏览器打开”等描述
- 如果确实找不到精确的目标子页面，退而求其次打开**最接近的有效页面**（如官网首页、产品主页、支持中心），并在输出中说明“这是目前能找到的最接近页面”
- 对于“找到 XXX 下 YYYY 相关页面”这类意图，优先打开**最相关的一个具体子页面**（如 Python3 教程页），而不是只打开首页；若存在多个强相关页面，可打开聚合入口/分类页
- 返回给用户的结构化输出中，必须包含一句明确说明页面已被打开的内容
- 如果未调用 `browser_open`，**必须返回错误并重新尝试调用，不得输出查找结果**
- 调用`browser_open`时，必须只调用一次，不得重复调用

### Step 5: 结构化输出

ALWAYS 使用以下模板返回结果：

```markdown
## 查找结果

### 目标
- **网站/产品：** [名称]
- **目标页面：** [页面类型]

### 站点信息
- **官网首页：** [URL]
- **目标页面：** [URL]
- **页面标题：** [从页面获取的标题]
- **页面描述：** [简要说明页面上有什么]

### 可用版本/选项
- **[版本名称]：** [直接链接]
  - 说明：[如适用平台、架构等]
- **[版本名称]：** [直接链接]
  - 说明：[如适用平台、架构等]
[如果没有多版本，移除此区域]

### 导航说明（如需要）
简要说明如何从首页到达该页面，或页面上有哪些主要内容。

### 浏览器打开结果
- **页面已打开**
[检查页面标题和内容是否与目标页面匹配]

```

## 常见问题处理

### 官网不易找到
- 同时尝试中文和英文搜索词
- 对于开源项目，检查 GitHub/GitLab（项目首页通常有 Release/Download 链接）
- 检查搜索结果中官方入口的特征——官网通常不会在 URL 中包含大量随机参数

### 多语言网站
- 部分网站有 `/zh/`、`/en/` 等语言前缀，自动匹配用户语言或提供双语选项
- 如果用户明确指定语言，优先查找该语言版本

### 需要登录才能访问
如 GitHub Releases 等，告知用户该页面需要登录才能看到具体下载链接。

### 页面访问失败（404/连接失败）
- 检查 URL 路径拼写是否有其他变体
- 返回首页，重新使用 `web_search_tool` 或 `web_fetch` 继续分析导航
- 如确实找不到，告知用户并提供最接近的 URL

### 动态加载的 SPA 页面
有些网站（如 React/Vue 单页应用）的 `web_fetch` 结果可能不含完整内容。这种情况下：
- 优先依赖 `web_search_tool` 搜索结果获取准确的子页面 URL
- 使用 `browser_open` 在默认浏览器中打开页面，让用户看到渲染后的内容

## 工具使用指南

### 1. 搜索官网

使用 `web_search_tool`：

```
查询：麒麟软件 官网
```

从搜索结果中提取官网首页 URL（如 `https://www.kylinos.cn`）。

### 2. 抓取首页分析导航

使用 `web_fetch` 抓取官网首页：

```
url: https://www.kylinos.cn
```

在返回内容中查找包含 `下载`、`Download` 等关键词的 `<a>` 标签，提取 `href`。

### 3. 搜索目标子页面（备用）

如果首页未找到明确入口，使用 `web_search_tool`：

```
查询：麒麟软件 下载
```

从搜索结果中筛选出官网子页面 URL。

### 4. 验证并打开最终页面

使用 `web_fetch` 验证候选 URL 可访问且内容匹配，然后必须使用 `browser_open` 在系统浏览器中打开：

```
url: https://www.kylinos.cn/download
```

### 链接提取技巧

| 场景 | 方法 | 说明 |
|------|------|------|
| 找下载入口 | `web_fetch` + 关键词匹配 | 在首页 HTML 中搜索 `下载`、`Download` |
| 找文档入口 | `web_fetch` + 关键词匹配 | 搜索 `文档`、`Docs`、`Documentation` |
| 找登录入口 | `web_fetch` + 关键词匹配 | 搜索 `登录`、`Login`、`Sign in` |
| 找不到入口 | `web_search_tool` | 直接搜索"网站名 + 页面类型" |
| 需要用户看到页面 | `browser_open` | 在系统浏览器中打开最终 URL |

### 示例：查找麒麟软件下载页面

```
用户需求：我想找到麒麟软件镜像官方下载页面，我用的电脑是 x86_64 架构的。

任务步骤：
1. 搜索官网：
   web_search_tool 查询：麒麟软件 官网
   → 确认官网首页：https://www.kylinos.cn

2. 抓取首页寻找下载入口：
   web_fetch url: https://www.kylinos.cn
   → 在 HTML 中查找包含"下载"的 <a> 标签
   → 假设找到：https://www.kylinos.cn/download

3. 如果首页找不到，直接搜索子页面：
   web_search_tool 查询：麒麟软件 下载
   → 从结果中筛选官网下载页面

4. 验证目标页面：
   web_fetch url: https://www.kylinos.cn/download
   → 确认页面可访问、包含下载内容

5. 在系统浏览器中打开，展示给用户：
   browser_open url: https://www.kylinos.cn/download

6. 按结构化模板返回结果，包含 x86_64 / amd64 版本镜像链接

注意事项：
- 优先从首页导航提取真实链接，避免构造不存在的路径
- 如果首页没有直接下载入口，尝试 /download 或 /download-center
- browser_open 用于最终展示，必须在确认 URL 有效后再调用
- 操作完成后报告：官网首页 URL、目标子页面 URL、页面标题、x86_64 版本下载链接
```

## 关键原则

1. **搜索 + 抓取优先** — 先用 `web_search_tool` 和 `web_fetch` 定位真实链接，不凭空构造路径
2. **必须打开浏览器** — 找到有效子页面 URL 后，**必须调用 `browser_open`** 用系统浏览器中打开；即使找不到精确页面，也必须打开最接近的有效页面，不能只输出链接或文字描述。输出中任何“页面已打开”类描述都必须对应真实的 `browser_open` 调用。
3. **验证优先** — 用 `web_fetch` 对候选 URL 做实际访问和内容匹配确认后再 `browser_open`
4. **结构化输出** — 始终使用上方模板返回结果，保持用户可读性
5. **诚实告知** — 如果找不到确切页面，如实告知并提供最佳近似结果，同时用 `browser_open` 打开该近似页面
6. **多语言支持** — 用户说中文则优先用中文搜索，但必要时也尝试英文
7. **多版本全列出** — 有多个版本/架构选项时全部列出，不替用户筛选
